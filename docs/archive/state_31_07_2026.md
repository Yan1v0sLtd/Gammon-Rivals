# Gammon-Rivals — State Report

> Date: 31 July 2026
> Trace of the project folder: product, architecture, backend endpoints and their callers, client structure.

---

## Product

A **real-time multiplayer backgammon game** — primarily a native Android app (Capacitor + Play Billing IAP), also deployable on web (Vite, `vercel.json`). Free-to-play, social-casino-style: virtual chips, entry-fee matches with prizes, daily retention loops, full shop. Explicitly **no real-money chips or cash-out** (regulatory framing, per `CLAUDE.md`).

## Architecture

Core principle (CLAUDE.md): a **pure, deterministic TS engine is the source of truth**; UI is a view. The engine is duplicated into two places, kept in sync by build scripts:

- `src/engine/` — board, rules, dice, match (doubling cube, Crawford, match play). ~20 test suites + fuzz tests.
- `supabase/functions/_shared/engine/` — same code server-side (via `scripts/build-shared-engine.mjs`) enabling **server-authoritative online play**: `roll_dice` rolls server-side, `commit_turn`/`finish_turn` validate moves, Realtime broadcasts state. Clients never trust their own dice.
- Same for AI: `src/ai/` (picker/evaluator/strength tiers, Web Worker) mirrors to `supabase/functions/_shared/ai/` so **server-side bots** stand in when matchmaking finds no human.

Rendering: PixiJS board (`src/board/`) with imperative `render(state)` API — no game state in Pixi. Theme system for purchasable board skins. 3D dice via `three`/`cannon-es`.

App layers:
- `src/game/` — `useGame` (local/hot-seat), `useOnlineGame` (~1300 lines, PvP session client).
- `src/lobby/` — engagement surface: profile card, board carousel, daily bonus, hourly wheel, daily missions, XP boosts, difficulty selection, onboarding tour.
- `src/lib/` — Supabase auth (guests + Google OAuth, native Google plugin), wallets/currency, progression (XP, levels, status tiers), billing.
- `src/lib/billing/` — plugin-agnostic `BillingService` (native Play Billing + mock); Google purchase validation edge function.
- `src/pages/Admin.tsx` + `src/admin/` — Back Office: operator tunes missions, wheel, economy configs, shop, board themes, loading-screen art, level configs without code changes.
- `src/sim/` — pure economy math (RTP/rake/payouts per tier), unit-tested.

Backend: Supabase, ~130 migrations. Evolution: auth/profiles → online PvP schema → matchmaking RPC → ELO → rooms/difficulties with entry fees → economy columns → AI-level escalator → daily bonuses → hourly wheel → personalized daily missions → shop seeding → IAP fulfillment → storefront config → payout derivation (rake, consolation, XP), RTP reports, stale-match abandonment.

Product loops:
- Core: entry-fee matches (PvP or AI fallback) → win coins/gems, lose to rake/house margin.
- Retention: daily bonus, hourly wheel, 4 daily missions (chests/streaks/gem-priced rerolls), XP boosts, level ladder with status tiers.
- Monetization: Google Play Billing IAP (coins/gems packs), gems spent on board skins + mission rerolls.

Note: README is a stock Vite template — `CLAUDE.md` is the real documentation.

## Backend endpoints and callers

### Edge functions (5 HTTP endpoints, `supabase/functions/`)

| Endpoint | Called by | Role |
|---|---|---|
| `roll_dice` | `src/game/useOnlineGame.ts` | Server-authoritative dice; writes via SERVICE ROLE; internally calls `commit_turn_server` RPC |
| `finish_turn` | `src/game/useOnlineGame.ts` | Replays recorded moves, derives cube/score state; calls `commit_turn_server` RPC (service role) |
| `ai_move` | `src/game/useOnlineGame.ts` | Bot turn in PvP; picks AI move, calls `commit_ai_turn` RPC |
| `validate-google-purchase` | `src/lib/billing/nativeBilling.ts` (raw fetch, not SDK) | Verifies Play receipt against Google API; calls `fulfill_google_purchase` (service role) |
| `validate_game` | no active caller found (validation utility, likely legacy) | — |

### RPCs (~40) grouped by caller domain

**Online play / matchmaking** — callers `src/lib/persistence.ts` + `src/game/useOnlineGame.ts`

```plaintext
matchmake / cancel_matchmaking           (legacy single-match path)
find_match_in_tier / cancel_matchmaking  (current tiered PvP)
enter_room_ai_fallback                   (AI stands in when no human)
join_public_match / join_match_by_invite
finish_match                             (payout + XP + ELO; from both persistence & useOnlineGame)
replace_opponent_with_ai                 (disconnector → bot)
abandon_stale_matches
commit_turn_server / commit_ai_turn      (server-internal, called by edge fns only)
```

**Player engagement loops** — callers in `src/lobby/`

```plaintext
claim_daily_bonus        ← LobbyScreen
spin_wheel / get_wheel_state            ← WheelModal / useWheelState
claim_mission / claim_streak_chest / reroll_mission / get_player_missions_today
                         ← DailyMissionsModal / useDailyMissions
purchase_board_with_gems ← LobbyScreen (board skins)
mark_tutorial_complete   ← LobbyScreen
get_player_lobby_stats   ← useLobbyProfileStats
```

**Shop / billing** — callers `src/pages/Shop.tsx`, `src/lib/shopCache.ts`, `src/lib/billing/mockBilling.ts`

```plaintext
purchase_shop_item       ← Shop.tsx (via player supabase client)
test_purchase_shop_item  ← mockBilling (no-money path)
current_store_sale       ← shopCache + Shop.tsx
```

**Back Office (admin only)** — callers `src/pages/Admin.tsx`, `src/admin/*`

```plaintext
get_my_admin_role         ← Admin.tsx (via adminSupabase) + Shop.tsx (via player client)
admin_adjust_wallet, admin_hard_delete_user,
admin_upsert_currency_config, admin_upsert_economy_grant   ← Admin.tsx
admin_refresh_player_missions, assign_daily_missions_for_profile,
simulate_* (7 fns)                                          ← MissionsAdmin.tsx
recompute_player_levels   ← LevelCurveProposal.tsx
set_active_podium / set_active_loading_screen               ← Admin.tsx
get_rtp_summary / get_rtp_per_player                        ← Admin.tsx (economy reports)
```

### Security model

```plaintext
Edge fns:   JWT auth (anon key + getUser) → DB writes as SERVICE ROLE,
            authorization checked inside (owner/opponent/turn)
Admin RPCs: security definer + private.can_manage_config(auth.uid()) gate
            (owner/admin only). Config tables have RLS with same gate.
Identity:   admin_roles (explicit grants) ∪ admin_email_allowlist (email→role)
            resolved by private.current_admin_role(); get_my_admin_role granted to authenticated
```

## Client structure (one SPA, one Vite build)

```plaintext
/ (web)         → public/landing.html (marketing) via vercel.json rewrite
/ (native)      → redirect → /play
/play           → AuthGate → Home = LobbyScreen      ← the actual product hub
/play/:matchId  → AuthGate → PlayOnline (useOnlineGame session)
/hotseat, /profile, /replay/:gameId, /join/:code
/shop           → deep link that opens the ShopProvider popup over the lobby
/delete-account → public (Play Store requirement), /auth/callback
/admin          → NOT AuthGate-wrapped; Admin.tsx self-gates via useAdminAuth + get_my_admin_role
/admin/auth/callback → PKCE OAuth return

Layers:
  src/game/        session hooks (useGame, useOnlineGame)
  src/board/       PixiJS renderer + themes
  src/lobby/       game hub (daily bonus, missions, wheel, boards, onboarding)
  src/lib/         player auth, supabase, billing, currency, progression
  src/components/  UI primitives + HUD (dice, cube, match header, timers)
  src/engine|ai|sim  pure TS, also mirrored server-side
  src/admin/ + src/pages/Admin.tsx   Back Office
```

## Session storage (summary)

Player sessions use a hybrid auth storage (see `src/lib/supabase.ts`); admin sessions use plain localStorage under a separate key (see `src/lib/adminSupabase.ts`). Details in the follow-up report on session persistence.
