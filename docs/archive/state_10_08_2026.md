## Product

Unchanged: a **real-time multiplayer backgammon game** — primarily a native Android app (Capacitor + Play Billing IAP), also deployable on web. Free-to-play, social-casino-style: virtual chips, entry-fee matches with prizes, daily retention loops, full shop. Explicitly **no real-money chips or cash-out** (regulatory framing, per `AGENTS.md`).

## Architecture

Core principle (AGENTS.md) unchanged: a **pure, deterministic TS engine is the source of truth**; UI is a view. The engine is duplicated into two places, kept in sync by build scripts:

- `packages/engine/src/` — board, rules, dice, match (doubling cube, Crawford, match play). ~20 test suites + fuzz tests. Imported through relative paths.
- `supabase/functions/_shared/engine/` — same code server-side (via `scripts/build-shared-engine.mjs`) enabling **server-authoritative online play**: `roll_dice` rolls server-side, `commit_turn`/`finish_turn` validate moves, Realtime broadcasts state. Clients never trust their own dice.
- Same for AI — `packages/ai/src/` (picker/evaluator/strength tiers, Web Worker bridge) mirrored to `supabase/functions/_shared/ai/` via `scripts/build-shared-ai.mjs` so **server-side bots** stand in when matchmaking finds no human.

Monorepo layout is now **three apps** (`apps/game/` player SPA port 5174, `apps/admin/` Back Office port 5175, **`apps/website/` Astro marketing/legal site** — new this period) plus `packages/engine|shared|board-renderer|board-preview|ai|sim|brand-assets`. App boundaries still enforced by `scripts/check-app-boundaries.mjs` (part of `build:all`).

### Security model — unchanged

```plaintext
Edge fns:   JWT auth (anon key + getUser) → DB writes as SERVICE ROLE,
            authorization checked inside (owner/opponent/turn)
Admin RPCs: security definer + private.can_manage_config(auth.uid()) gate
            (owner/admin only). Config tables have RLS with same gate.
Identity:   admin_roles (explicit grants) ∪ admin_email_allowlist (email→role)
            resolved by private.current_admin_role(); get_my_admin_role granted to authenticated
```

## Client structure (three apps, three builds)

```plaintext
apps/website/  (Astro, dist/web — the document root)
/                   → index (marketing hero)

    robots.txt + sw.js + .well-known/security.txt copied in at build

/ (native)  → redirect → /play (App.tsx IndexRedirect, no server rewrite in WebView)
/play           → AuthGate → Home = LobbyScreen      ← the actual product hub
/play/:matchId  → AuthGate → PlayOnline (onlineMatch feature session)
/hotseat, /profile, /replay/:gameId

apps/admin/  (Back Office, dist/admin, own origin under /admin)
/               → AdminAuthGate → Admin shell (14 sections, URL-routed)
/auth/callback  → AdminAuthCallback (PKCE OAuth return)
/admin/<section> deep links fall back to the SPA index (nginx)
```
