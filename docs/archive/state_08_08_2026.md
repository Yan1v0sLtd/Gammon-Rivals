## Product

A **real-time multiplayer backgammon game** — primarily a native Android app (Capacitor + Play Billing IAP), also deployable on web. Free-to-play, social-casino-style: virtual chips, entry-fee matches with prizes, daily retention loops, full shop. Explicitly **no real-money chips or cash-out** (regulatory framing, per `CLAUDE.md`).

## Architecture

Core principle (CLAUDE.md): a **pure, deterministic TS engine is the source of truth**; UI is a view. The engine is duplicated into two places, kept in sync by build scripts:

- `packages/engine/src/` — board, rules, dice, match (doubling cube, Crawford, match play). ~20 test suites + fuzz tests. Imported through relative paths.
- `supabase/functions/_shared/engine/` — same code server-side (via `scripts/build-shared-engine.mjs`) enabling **server-authoritative online play**: `roll_dice` rolls server-side, `commit_turn`/`finish_turn` validate moves, Realtime broadcasts state. Clients never trust their own dice.
- Same for AI — `packages/ai/src/` (picker/evaluator/strength tiers, Web Worker bridge) mirrored to `supabase/functions/_shared/ai/` via `scripts/build-shared-ai.mjs` so **server-side bots** stand in when matchmaking finds no human.

Monorepo layout (two apps, one repo, one Supabase project) is unchanged since the split: `apps/game/` (player SPA, port 5174), `apps/admin/` (Back Office, port 5175), `packages/engine|shared|board-renderer|board-preview|ai|sim`. App boundaries still enforced by `scripts/check-app-boundaries.mjs` (part of `build:all`).

### Rendering & UI performance (4–5 Aug)

A focused campaign driven by `reports/game-ui-performance-trace.md` (9c286f0), which found: duplicated CSS-hidden mobile/desktop panel trees with duplicated 220 ms `TurnTimerBar` intervals, no memo bailouts around `BoardLayout`/`SidePanel`, fresh identities from page-level JSX/objects, and `DiceTray` recomputation per submove. Fixes:

- **43ef90d** (4 Aug): `BoardRenderer` split into **five persistent layers** (board, checkers, selection, interaction, animation), each with an independent rebuild lifecycle — board and position layers rebuild only on state/layout change; RAF ticks clear and redraw only the animation layer; resize early-returns on unchanged dimensions; explicit `Container` targets; dead parameters dropped.
- **3607dc7** (5 Aug): connected surfaces + a demand-driven renderer scheduler — stable timer/board/selection/interaction selectors; timer ticking moved into `TurnTimerBar` (page-level intervals dropped); memoized `HotSeatBoardSurface`/`OnlineBoardSurface` replace page-level board wiring; `BoardCanvas` split into explicit per-concern update paths; the renderer requests RAF frames only when something changed (`scheduledFrame`), with perf marks (`pixi.layer.board/checkers/selection/interaction.rebuild`, 3ef6f3c).
- **d81ad78 / 6fb1f3f** (5 Aug, duplicate commit of the same change): panel data read in **connected leaves** — gameplay/online panel+header display selectors; `SidePanel` split into memoized shell/identity/stat leaves; `PlayerSeat` prop drilling replaced by `BoardLayout` panel node slots; pip/score/cube/timer reads per-stat leaf; spectator header names and the signed-out guest identity resolved in selectors.
- **42a4558** (5 Aug): new `useMediaQuery` hook; the CSS-hidden duplicate side-panel trees (trace finding #1) now mount conditionally by media query instead of rendering both layouts.

### CSS Modules migration (5–8 Aug) — the headline of the period

Full campaign per `reports/css-modules-migration-state.md` (slices S1–S15, C0–C8, S16/C9): `apps/game/src/index.css` went from the ~10 280-line monolith to **18 lines** (Tailwind entry directives + document base styles only). Mechanics:

- Co-located **camelCase CSS Modules** for every migrated component, each carrying its own keyframes and responsive rules; `apps/game/vite.config.ts` sets `css.modules.localsConvention: "camelCaseOnly"`.
- `apps/game/src/keyframes.css` holds shared cross-consumer keyframes; `apps/game/src/styles/shared.module.css` holds shared styles composed in via `composes:` (`fontDisplay`, `textWhite`, `actionButtonReset`, `actionButtonChrome`) — no CSS custom properties for sharing (user preference).
- Cascade parity preserved per slice: pass-order, media interleave, specificity compounds (`.right.timer`, `.sideRight.row`, `.timer.warning .fill`), global keyframes referenced via `global(...)`, side-mirroring via `side` props instead of parent-scoped selectors (C2/C5/C6/C7), caller-positioning contract via `:where()` zero-specificity defaults (R2).
- **Dead CSS purged**: S15 dead-lobby purge (−1 518 lines), C0 dead-gameplay purge (−562), per-slice removals; `DoublingCube.tsx` deleted as dead code (C8). Shared resets consolidated (`actionButtonReset`/`actionButtonChrome`), replacing the old grouped global rules (C1/C3).
- Game-app Tailwind utilities decomposed out of `className` across every migrated component; the final batch (S16/C9, 8 Aug) covered the last 15 game targets (AlignmentPanel, AuthGate, Avatar, RouteErrorBoundary, BoardLockTooltip, LobbyModalHost, OnboardingTour, XpBoostBadge, BoardPurchaseModal, DifficultyModal, HowToPlayModal, AuthCallback, DeleteAccount, PlayOnline, Replay) + `ModalCloseButton`. **Zero Tailwind utility classes remain in the game app's TSX.**
- Conventions codified in `.claude/skills/css-modules/SKILL.md`; two pre-existing `index.css` syntax bugs fixed along the way (unclosed comment, stray brace); the earlier Lightning CSS arm64 binary blocker cleared; `npm run build` passes.
- **Remaining** (migration plan steps 7–9): Tailwind conversion in `apps/admin/src` + `packages/board-renderer`/`packages/board-preview`; Tailwind config/dependency removal (`tailwind.config.js`, `tailwind.admin.config.js`, postcss); final `build:all`. Browser/manual visual checks remain pending for the completed slices.

## Session storage (summary)

Player sessions use a hybrid auth storage (see `apps/game/src/lib/supabase.ts`); admin sessions use plain localStorage under a separate key (see `apps/admin/src/lib/adminSupabase.ts`). The two apps keep independent auth — player and admin sessions can coexist in the same browser. Details in the follow-up report on session persistence.
