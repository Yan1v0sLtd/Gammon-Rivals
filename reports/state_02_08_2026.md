## Product

A **real-time multiplayer backgammon game** — primarily a native Android app (Capacitor + Play Billing IAP), also deployable on web (Vite, `vercel.json`). Free-to-play, social-casino-style: virtual chips, entry-fee matches with prizes, daily retention loops, full shop. Explicitly **no real-money chips or cash-out** (regulatory framing, per `CLAUDE.md`).

## Architecture

Core principle (CLAUDE.md): a **pure, deterministic TS engine is the source of truth**; UI is a view. The engine is duplicated into two places, kept in sync by build scripts:

- `packages/engine/src/` — board, rules, dice, match (doubling cube, Crawford, match play). ~20 test suites + fuzz tests. Imported through relative paths.
- `supabase/functions/_shared/engine/` — same code server-side (via `scripts/build-shared-engine.mjs`) enabling **server-authoritative online play**: `roll_dice` rolls server-side, `commit_turn`/`finish_turn` validate moves, Realtime broadcasts state. Clients never trust their own dice.
- Same for AI — now a package: `packages/ai/src/` (picker/evaluator/strength tiers, Web Worker bridge) mirrored to `supabase/functions/_shared/ai/` via `scripts/build-shared-ai.mjs` so **server-side bots** stand in when matchmaking finds no human.

### Monorepo restructure (the big change since 31.07)

Two independent applications, one repository, one Supabase project. Goal doc: `reports/split-admin-app-goal.md` (7 phases); phases 1–5 done, **phase 6 (admin data-access boundary) and phase 7 (separate-origin deploy, OAuth redirect allowlist, coexistence validation) are still open**.

- `apps/game/` — player SPA (Vite, port 5174, builds to `dist/`).
- `apps/admin/` — Back Office SPA (Vite, port 5175, builds to `dist-admin/`, own `tailwind.admin.config.js`).
- `packages/engine/` — pure rules engine (no imports outside its package).
- `packages/shared/` — DB types, currency, progression, errors, `clientBootstrap`.
- `packages/board-renderer/` — shared Pixi renderer, geometry, themes; now also owns `theme/metadata.ts` (`layoutFromMetadata` — the BO JSON layout contract parsed with the same code the admin preview uses).
- `packages/board-preview/` — admin-only board preview, composed from engine + renderer.

App boundaries are **enforced by script**: `scripts/check-app-boundaries.mjs` (run by `npm run check:boundaries`, part of `build:all`) fails the build if the game imports admin or vice versa, if admin UI imports engine/renderer code instead of board-preview, if any package imports app code, or if engine/shared import outside their package. Local modules use relative imports.

### Build & bundling

- Shared Vite config `config/vite.shared.ts`: `projectRoot`, `buildDefines()` (injects `__APP_BUILD_COMMIT__` from `VERCEL_GIT_COMMIT_SHA` and `__APP_BUILD_TIME__`), and `vendorChunkGroups()` — ~30 vendor packages (pixi.js, react, react-dom, router, supabase-js family, sentry, capacitor, billing plugin, etc.) each split into its own chunk so the main bundle stays small.
- Build scripts now run `cross-env NODE_ENV=production` (commit 4c14e76) + `tsc -b`; per-app tsconfigs (`apps/game/tsconfig.json`, `apps/admin/tsconfig.json`) extend `tsconfig.base.json`.
- `packages/shared/src/clientBootstrap.ts` — both apps init through it: Sentry (production only, release = `app@commit`), `window.__BUILD__`, and **stale-chunk auto-reload** (detects `ChunkLoadError` / MIME errors, reloads once per session via a sessionStorage flag — a hard requirement once vendor chunks exist).
- ESLint flat config (`eslint.config.js`, eslint now a devDependency): recommended + typescript-eslint + react-hooks + react-refresh, two experimental hooks rules disabled; fixes phase 1 landed (commit 24cd37b).
- Tests via root `vitest.config.ts`, scoped to `packages/**` — engine rules, AI decision logic, economy sim, board hit-area geometry. Client-side tests were removed (see below); `npm run sim` runs the economy/AI report as tooling.

### Redux state management (player app)

- Redux Toolkit (`@reduxjs/toolkit` 2.x + `react-redux` 9.x) is now the player-app state framework; RTK Query is the only server cache. Store in `apps/game/src/store/`: `store.ts` (strict `configureStore` — default serializable/immutable checks kept, `devTools` dev-only), `hooks.ts` (typed `useAppDispatch`/`useAppSelector`), `listenerMiddleware.ts` (cancellable delayed workflows), `baseApi.ts` (the single shared `createApi` with `fakeBaseQuery<ApiError>`).
- Features live in `apps/game/src/features/<feature>/` and inject endpoints into `baseApi` — never a second `createApi`. RTK Query results are never copied into ordinary slices; slices hold only serializable UI state.
- Pilot — Replay: `features/replay/replayApi.ts` injects `getReplay(gameId)` → `features/replay/replayData.ts` `getGameWithMoves` (1800 s unused-cache retention, single attempt, plain `{message}` errors). `features/replay/replaySlice.ts` holds only `ply`/`playing` via a fresh-state factory. `features/replay/replaySelectors.ts` reconstructs boards from persisted `sub_moves` with engine `initialBoard`/`applyMove`/`endTurn` and derives clamped ply/current board. The 1400 ms playback cadence runs in listener middleware; route entry/exit resets the slice, never the API cache.
- Policy: packages are tested, apps are not. The client-side suites covering reducers, selectors, listener timing/cancellation and RTK Query endpoints (`features/replay/*.test.ts`, `store/listenerMiddleware.test.ts`) were deleted — they churned faster than they caught bugs. Pure logic that deserved tests (AI, sim) was moved into `packages/` instead. Do not reintroduce client tests without discussion.

### Known performance debt

`reports/pixi-usage-optimization.md`: Pixi is imported by only 3 files (BoardCanvas, theme loader, BoardRenderer) and is route-lazy, but the chunk is **518 kB minified / 148 kB gzip**. `BoardRenderer.drawScene()` rebuilds the whole scene on every frame. Planned order: persistent renderer layers → lazy-load admin board preview → drop theme `HEAD` preflight requests → selective Pixi build → Canvas 2D only as a last resort.

Rendering: PixiJS board with imperative `render(state)` API — no game state in Pixi. Theme system for purchasable board skins; `apps/game/src/board/theme/remote.ts` resolves themes: explicit `?board=` param → player's persisted lobby pick → first enabled BO board by `sort_order` → bundled placeholder (`premiumTheme`). 3D dice via `three`/`cannon-es`.

App layers:
- `apps/game/src/game/` — `useGame` (local/hot-seat), `useOnlineGame` (~1300 lines, PvP session client).
- `apps/game/src/lobby/` — engagement surface: profile card, board carousel, daily bonus, hourly wheel, daily missions, XP boosts, difficulty selection, onboarding tour.
- `apps/game/src/lib/` — Supabase auth (guests + Google OAuth, native Google plugin), wallets/currency, progression (XP, levels, status tiers), billing.
- `apps/game/src/store/` — Redux store, typed hooks, listener middleware, shared RTK Query API.
- `apps/game/src/features/` — per-feature slices, injected endpoints, selectors, listener workflows and Supabase data access (one directory per feature).
- `apps/game/src/lib/billing/` — plugin-agnostic `BillingService` (native Play Billing + mock); Google purchase validation edge function. Web mock now returns "not authorized" — purchases are native-only; operator grant flows moved to the Back Office.
- `apps/admin/src/` — Back Office: operator tunes missions, wheel, economy configs, shop, board themes, loading-screen art, level configs without code changes. Own router, own auth (`adminAuth`, `adminSupabase`), lazy-loaded routes.
- `packages/sim/src/` — pure economy math (RTP/rake/payouts per tier) plus `runSim.ts`, the Monte-Carlo economy + AI-ladder harness run via `npm run sim`. Unit-tested; the report itself is tooling.

Backend: Supabase, ~130 migrations — unchanged this period. Evolution: auth/profiles → online PvP schema → matchmaking RPC → ELO → rooms/difficulties with entry fees → economy columns → AI-level escalator → daily bonuses → hourly wheel → personalized daily missions → shop seeding → IAP fulfillment → storefront config → payout derivation (rake, consolation, XP), RTP reports, stale-match abandonment.

Product loops:
- Core: entry-fee matches (PvP or AI fallback) → win coins/gems, lose to rake/house margin.
- Retention: daily bonus, hourly wheel, 4 daily missions (chests/streaks/gem-priced rerolls), XP boosts, level ladder with status tiers.
- Monetization: Google Play Billing IAP (coins/gems packs), gems spent on board skins + mission rerolls.

### Security model — unchanged

```
Edge fns:   JWT auth (anon key + getUser) → DB writes as SERVICE ROLE,
            authorization checked inside (owner/opponent/turn)

            (owner/admin only). Config tables have RLS with same gate.
Identity:   admin_roles (explicit grants) ∪ admin_email_allowlist (email→role)
            resolved by private.current_admin_role(); get_my_admin_role granted to authenticated

## Client structure (two SPAs, two Vite builds)

```
apps/game/  (web + native bundle)

Layers:

- `apps/game/src/lobby/` — game hub (daily bonus, missions, wheel, boards, onboarding)

## Session storage (summary)

Player sessions use a hybrid auth storage (see `apps/game/src/lib/supabase.ts`); admin sessions use plain localStorage under a separate key (see `apps/admin/src/lib/adminSupabase.ts`). The two apps keep independent auth — player and admin sessions can coexist in the same browser. Details in the follow-up report on session persistence.
